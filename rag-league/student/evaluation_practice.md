# 개발용 평가 질문 10문항 (공개)

> 이 10문항은 **개발·튜닝 전용 공개 세트**입니다.
> 이 문서는 학생용 공개 DEV 10문항과 정답 근거 안내입니다. 교수자 전용 평가 파일이나 Private 저장소 접근은 필요하지 않습니다.

| 항목 | 값 |
|---|---|
| 문항 수 | **10** (답변 가능 **8** / 정보 부족 **2**) |
| 정답 근거 | **공개** (아래 표에 페이지까지 제시) |
| 비공개 평가셋과의 중복 | **없음** (자동 검사로 확인) |
| 용도 | Hit@5 측정, 거부 임계값 튜닝, 파이프라인 동작 확인 |

---

## 1. ⚠️ 사용 원칙 — 먼저 읽으십시오

| 하십시오 ✅ | 하지 마십시오 ❌ |
|---|---|
| 파이프라인 동작 확인 | 이 10문항에 **과적합** |
| Hit@5 베이스라인 측정 | 10문항만 맞추도록 하드코딩·예외 처리 |
| 거부 임계값 튜닝 | 이 문항들의 정답을 데이터에 주입 |
| 프롬프트 개선 | 10문항 결과로 "우리 시스템은 100%"라고 결론 |

> **10문항은 표본이 너무 작습니다.** 임계값을 소수점 아래까지 맞추면
> 비공개 평가에서 오히려 나빠집니다.
> 또 비공개 평가는 **여러 질문 유형**을 포함하며 공개 DEV보다 **더 어려울 수 있습니다.**

---

## 2. 비공개 평가셋과의 관계

| | 공개 개발셋 | 비공개 평가셋 |
|---|---|---|
| 문항 수 | 10 | 약 100문항 규모 |
| 질문 공개 | 지금 | ❌ (주최측 Runner가 팀 Agent endpoint로 전송) |
| 정답 공개 | ✅ | ❌ |
| 유형 | 사양 중심 + 모델 구분 2 + 정보 부족 2 | 여러 유형 (근거 없는 질문 포함 가능, 구성 비공개) |
| 난이도 | 낮음~중간 | **중간~높음** |

→ **개발셋을 다 맞춰도 비공개셋에서 60%를 못 넘길 수 있습니다.**
   특히 "복합 조건·예외 처리"와 "유사 제품 간 기능 구분"을 의식적으로 준비하십시오.

## 5. 이 10문항으로 측정할 것

### 5.1 Hit@5 (DAY 2 완료 기준)
```
Hit@5 = 상위 5개 검색 결과에 위 표의 출처 페이지가 포함된 문항 수 / 8
```
(정보 부족 2문항은 분모에서 제외합니다 — 정답 근거가 없으므로)

| Hit@5 | 판단 |
|---|---|
| 6/8 이상 (0.75+) | 좋음 |
| 4~5/8 | 보통. 청킹·토큰화 점검 |
| 3/8 이하 | **문제 있음.** DAY 3 전에 원인 규명 |

### 5.2 거부 임계값 튜닝 (DAY 3)

| 결과 | 조치 |
|---|---|
| 8개 답변 + 2개 거부 | 이상적. 그대로 두십시오 |
| 답변 가능 문항을 거부 | 임계값을 **낮추십시오** |
| 정보 부족 문항에 답변 | 임계값을 **높이십시오** |

### 5.3 자체 채점 안내

공개된 DEV 질문 10개를 팀 Agent에 입력하고, 각 응답의 답변·근거 페이지·정보 부족 시 답변 보류 여부를 이 문서와 직접 대조하세요. 교수자 전용 평가 스크립트나 Private 저장소 파일은 학생 배포 자료에 포함되지 않습니다.

## 6. 자체 평가셋을 늘리는 방법 (권장)

10문항은 부족합니다. **직접 20~30문항을 더 만드십시오.**

### 만드는 요령
1. 설명서에서 **모델별로 값이 다른 사양**을 찾으십시오 (소비 전력, 중량, 속도, LCD, 메모리).
2. `관련 모델:` 마커가 붙은 절을 찾아 **그 모델 전용 기능** 질문을 만드십시오.
3. 표 각주(`~만 해당`)를 이용해 **복합 조건** 질문을 만드십시오.
4. 공식 자료에 **없는 정보**(가격, 출시일, 판매량)로 정보 부족 문항을 만드십시오.
5. 각 문항에 **출처 PDF 페이지를 반드시 기록**하십시오. 기록이 없으면 채점할 수 없습니다.

### 주의
- 비공개 평가셋 문항을 **추측해서 맞히려 하지 마십시오.** 시간 낭비입니다.
- 대신 **유형**을 흉내내십시오: 유사 제품 구분, 복합 조건, 모델 한정 기능.
